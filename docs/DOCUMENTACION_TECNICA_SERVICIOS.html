Applia — Documentación técnica (stack, APIs y arquitectura)

Documento orientado a equipos técnicos: lenguajes en front y back, frameworks y su relación con el lenguaje, APIs externas integradas y visión de arquitectura del monorepositorio.

Resumen ejecutivo

Applia es una plataforma web de servicios y reservas. El núcleo de la aplicación está escrito en TypeScript: un cliente React empaquetado con Vite y un servidor Node.js con Express. La base de datos documentada para este stack es Firebase en modo NoSQL (Cloud Firestore), junto con Auth y notificaciones (FCM) según configuración. Complementamos con mapas y rutas vía APIs públicas y de terceros.

Este HTML vive en docs/DOCUMENTACION_TECNICA_SERVICIOS.html y complementa al README.md raíz.

Lenguajes utilizados

Front-end (web)

El front-end corre en el navegador como una SPA hecha con React. El código fuente se escribe principalmente en TypeScript (TSX/JSX) y en desarrollo se sirve con Vite (dev server con HMR); en producción Vite genera el bundle optimizado en JavaScript/CSS que se entrega como archivos estáticos.

  • TypeScript — lenguaje principal del código de la app (tipado estático sobre JavaScript).
  • JavaScript — resultado de compilación y ecosistema Node/npm; parte del tooling y dependencias.
  • JSX / TSX — sintaxis de componentes React en archivos .tsx (TypeScript + XML-like).
  • HTML — plantilla de entrada (client/index.html) y fragmentos en documentación.
  • CSS — estilos en cascada; en el proyecto predominan utilidades que compilan a CSS.
  • React — biblioteca de UI con la que se construyen pantallas y componentes (código en TS/JS + JSX/TSX).
  • Vite — herramienta de desarrollo y empaquetado del front-end (config y plugins en TypeScript/JavaScript).
  • Tailwind CSS — framework de estilos utility-first; se escribe como clases en TSX y genera CSS.

Back-end y scripts (servidor)

El back-end corre sobre Node.js. El código fuente se escribe principalmente en TypeScript y se ejecuta en desarrollo con tsx; en producción el arranque usa el bundle JavaScript (dist/index.cjs) generado al compilar.

  • Node.js — motor de ejecución (runtime) del servidor: APIs HTTP, WebSockets, acceso a archivos y red. Versión recomendada según README.md del repo (p. ej. 18+).
  • TypeScript — lenguaje en el que está escrito casi todo el código del servidor: rutas REST (server/), integraciones, sockets, servicios y scripts de mantenimiento (script/).
  • JavaScript (ECMAScript) — lenguaje que Node ejecuta tras la compilación del servidor; también usado por dependencias npm y por el archivo de salida de producción.
  • JSON — formato habitual de cuerpos y respuestas en las APIs REST (application/json).
  • Express — framework HTTP sobre Node (no es un lenguaje aparte: la app se escribe en TypeScript/JavaScript usando su API).
  • Socket.IO — capa de tiempo real sobre Node (mismo ecosistema TS/JS que el resto del servidor).

Base de datos y datos

  • Firebase (NoSQL) — almacenamiento principal en Cloud Firestore (documentos y colecciones, sin modelo relacional SQL en esta capa). El cliente usa el SDK firebase; el servidor puede usar firebase-admin y/o @google-cloud/firestore según el módulo.

Compartido

  • TypeScript — tipos, flags y utilidades en shared/ consumidas por cliente y servidor.

Android (TWA / capa nativa ligera)

  • Java — proyecto Gradle bajo app/src/main/java/... (Trusted Web Activity u orientación similar).
  • Groovy / Kotlin DSL — scripts de build Gradle (build.gradle, settings.gradle).

Documentación y otros

  • Markdown — README.md, comparativas, notas en repo.
  • HTML — este documento y otros en docs/ o client/public/.

Frameworks, librerías y herramientas (y su lenguaje)

Nombre Qué es Lenguaje / ecosistema
React Biblioteca de interfaz de usuario (componentes, estado, virtual DOM). Se usa con TypeScript (archivos .tsx). El lenguaje de implementación es TypeScript/JavaScript.
Vite Herramienta de build (empaquetado) y servidor de desarrollo (HMR). Orquesta el proyecto front-end; con @vitejs/plugin-react compila JSX/TSX de React. Vite está implementado en TypeScript/JavaScript y se usa para desarrollar y construir el front-end. No es un “framework de React”: React es la biblioteca de UI; Vite es el motor de empaquetado y dev server del lado del tooling.
Express Framework HTTP minimalista para APIs y middleware. JavaScript / TypeScript sobre Node.js (server/).
Firebase SDK / Admin Cliente y servidor para Auth, Firestore (NoSQL), Cloud Messaging, etc. TypeScript/JavaScript (APIs del SDK de Google/Firebase).
Socket.IO Comunicación en tiempo real (WebSocket con fallback). Cliente y servidor en TypeScript/JavaScript.
Wouter Enrutador ligero para React. TypeScript/JavaScript.
TanStack Query Caché y fetching de datos en el cliente. TypeScript/JavaScript.
shadcn/ui + Radix Componentes accesibles y sistema de diseño. TypeScript/React.
Tailwind CSS Framework CSS utility-first. Configuración y clases en CSS/HTML vía plantillas TSX.
Leaflet + react-leaflet Mapas interactivos en el cliente. JavaScript/TypeScript.
Zod Validación de esquemas (API y formularios). TypeScript/JavaScript.
Passport / openid-client Autenticación (local, OAuth/OIDC según configuración). JavaScript/TypeScript en Node.
Nota sobre Vite y React: en documentación informal a veces se dice “stack Vite + React”. Lo correcto es: React es la biblioteca de interfaz (lenguaje: TypeScript/JS con JSX); Vite es la herramienta que compila y sirve ese código en desarrollo y producción (lenguaje del proyecto Vite: TS/JS).

APIs y servicios externos (integraciones)

Lista basada en dependencias y rutas del repositorio; algunas requieren variables de entorno o están detrás de nuestro propio API.

Mapas, geocodificación y rutas

  • Google Maps Platform — Geocoding, Places, Distance Matrix, etc. (client/src/lib/google-maps.ts).
  • OpenStreetMap Nominatim — geocodificación / búsqueda de lugares (server/routes-maps.ts).
  • OSRM / instancias de routing OSM — cálculo de rutas (p. ej. routing.openstreetmap.de, router.project-osrm.org).
  • OpenRouteService — direcciones alternativas si hay API key configurada (api.openrouteservice.org).

Identidad, datos en la nube y notificaciones

  • Firebase — cliente (firebase) y admin (firebase-admin): Auth, Firestore, Cloud Messaging (push), según configuración.
  • Google Cloud Firestore — SDK @google-cloud/firestore donde aplique.

Vehículos y datos públicos

  • NHTSA vPIC API — marcas/modelos de vehículos (EE. UU., sin API key) — client/src/lib/nhtsa-vpic.ts.

Autenticación / plataforma

  • Replit OIDC — integración opcional (server/replit_integrations/auth/replitAuth.ts, issuer Replit).

Contenido remoto

  • Unsplash u otras URLs HTTPS — imágenes de ejemplo en seeds/catálogo (server/storage-applia.ts, etc.).

Arquitectura y estructura del proyecto

Patrón general

  • Monorepositorio con tres capas lógicas: client/ (SPA React), server/ (API + estáticos en prod), shared/ (código común).
  • API REST bajo prefijos como /api/... definidos en Express (server/routes.ts y módulos registrados).
  • Tiempo real con Socket.IO para eventos de viajes, presencia de conductores, etc.
  • Capa de datos: Firebase Firestore (NoSQL) como almacenamiento documental; Auth y FCM según necesidad.
  • Autenticación: sesiones y/o JWT según flujos; integraciones con Firebase Auth donde corresponda.
